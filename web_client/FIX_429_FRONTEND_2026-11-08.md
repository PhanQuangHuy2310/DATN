# Giảm lỗi 429 Too Many Requests – Frontend only

Đã rà soát các API có tần suất gọi cao trong frontend DATN. Không thay đổi Django middleware, giới hạn đăng nhập, Redis, Supabase, Docker, AI service hay API contract.

## Nguyên nhân trong mã nguồn gốc

- Django `ApiRateLimitMiddleware` đếm số lượt truy cập `/api/v1/` theo IP, mặc định 300 lượt mỗi 60 giây (giá trị thực có thể đặt trong `EAS_API_RATE_LIMIT_PER_MINUTE`). Các tab localhost dùng chung IP.
- Frontend gọi `/auth/csrf` khi bootstrap và mỗi lần đăng nhập; khi lỗi 429 còn tự thử lại nhanh mà không đợi `Retry-After`.
- Các màn quản trị AI và quy chế polling mỗi 1,5 giây và 2,5 giây dù không có tác vụ cần cập nhật liên tục.
- `/system/ai-status` polling từ hai portal chưa dùng chung cơ chế tạm dừng request khi Django 429.

## Sửa trong frontend

1. `src/api.js`: tôn trọng `Retry-After` của mã `RATE_LIMIT_EXCEEDED`; không gửi request khác đến `/api/v1/` trong thời gian giới hạn, vẫn cho phép `/health/*`; phân biệt giới hạn toàn API với `LOGIN_RATE_LIMITED` riêng của đăng nhập.
2. `src/api.js`: dùng lại CSRF cookie đã có, đồng thời gộp các lần khởi tạo CSRF đang chờ trong một tab.
3. `src/App.jsx`: bootstrap phiên đăng nhập chờ hết `Retry-After` khi nhận 429; API trạng thái AI dùng chung client và lịch polling không vượt qua thời gian chờ khi đổi tab.
4. `src/components/AiEngineManagementPage.jsx`: chỉ một request một lần, hỏi 5 giây khi đang đồng bộ, 30 giây khi bình thường, 90 giây khi tab ẩn; tôn trọng 429.
5. `src/components/RegulationsManagementPage.jsx`: polling 30 giây khi tab hiển thị thay cho 2,5 giây không điều kiện.
6. `src/domain.js`: hiển thị thông báo tiếng Việt rõ ràng cho `RATE_LIMIT_EXCEEDED`.
7. `e2e/rate-limit-protection.test.mjs`: thêm test tự động cho các thay đổi trên.

## Cập nhật trên Windows

Giải nén file patch ở thư mục project gốc `D:\Đồ án\DATN`, ghi đè các file `web_client` cùng tên. Giữ nguyên `.env` và tất cả backend.

- Tắt các Vite frontend cũ và mở lại: `start_frontend_local.cmd`, `start_admin_local.cmd`.
- Đóng các tab cũ, để hết cửa sổ 60 giây rate limit từ Redis, sau đó tải lại một lần.
- Nếu muốn xác minh giới hạn thực của Django (chỉ đọc, không đổi):
  `\.venv\Scripts\python.exe manage.py shell -c "from django.conf import settings; print(settings.EAS_API_RATE_LIMIT_PER_MINUTE)"`.
- Kiểm tra trình duyệt Network: `/auth/csrf` không phải gọi liên tiếp khi đã có cookie; `/system/ai-status` không phải xuất hiện hàng loạt 429.
- Chạy tests: `cd web_client && npm test`.

**Giới hạn kiểm tra:** Đã chạy Node test; chưa chạy `npm run build`/kiểm thử trực tiếp với Supabase trong môi trường này vì thiếu `node_modules`.
