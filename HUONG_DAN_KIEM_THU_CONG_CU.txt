1.3. Bước 2 — Thiết lập Postman (Collection, Environment & CSRF Token)
--------------------------------------------------------------------------------
1) Mở Postman -> Chọn "Collections" -> Nhấn "+" để tạo Collection mới tên:
     EAS_API_Testing
2) Nhấn biểu tượng "Environments" (góc trên bên phải) -> Tạo Environment tên "EAS_Local"
   với các biến:
     - base_url         = http://127.0.0.1:8000
     - csrftoken        = (để trống)
     - request_id       = (UUID 1 đơn của chính user đăng nhập)
     - other_request_id = (UUID 1 đơn thuộc nhân viên/phòng ban khác)
     - template_id      = (UUID 1 loại yêu cầu lấy từ trường "id" của GET /api/v1/admin/request-templates)
   Nhớ chọn "EAS_Local" làm Environment đang kích hoạt ở góc trên bên phải!

3) BẮT BUỘC — Tạo Request (0) lấy CSRF Token (tránh lỗi 403 CSRF khi POST/PATCH):
   Vì Django bật CsrfViewMiddleware cho các phương thức thay đổi dữ liệu (kể cả login),
   hãy tạo Request đầu tiên trong Collection:
     - Tên    : 0. Get CSRF Token
     - Method : GET
     - URL    : {{base_url}}/api/v1/auth/csrf
   - Mở tab "Scripts" -> "Post-response" (bản cũ là tab "Tests"), dán đoạn mã:
       const csrfCookie = pm.cookies.get("csrftoken");
       if (csrfCookie) {
         pm.environment.set("csrftoken", csrfCookie);
       }
   - Nhấn "Send" -> Kiểm tra status 200 OK. Từ lúc này Postman tự lưu Cookie Jar cho
     127.0.0.1 và biến {{csrftoken}} đã có giá trị.
   - Ở mọi Request POST/PATCH bên dưới, luôn thêm 2 Header:
       X-CSRFToken : {{csrftoken}}
       Origin      : http://127.0.0.1:5173    (hoặc http://127.0.0.1:8080)


1.4. Bước 3 — Thực hiện 4 Request chính và chụp ảnh kết quả
--------------------------------------------------------------------------------
(1) Request 1: Kiểm tra Đăng nhập (200 OK & Cookie HttpOnly)
    - Method & URL : POST {{base_url}}/api/v1/auth/login
    - Headers      :
        Content-Type : application/json
        X-CSRFToken  : {{csrftoken}}
        Origin       : http://127.0.0.1:5173
    - Body (raw -> JSON):
        {
          "email": "hung.nguyen@eas.com",
          "password": "<MAT_KHAU_DEV_CUA_BAN>"
        }
    - Kiểm chứng & Chụp ảnh:
      * Status: 200 OK, Body JSON có trường "user" và "correlation_id".
      * Mở tab "Cookies" ở khung Response -> thấy cookie "eas_session" có thuộc tính
        HttpOnly = true, SameSite = Lax.
    - (Mở rộng test Rate Limit 429 & Retry-After):
      * Gửi sai mật khẩu >= 5 lần liên tiếp -> API trả HTTP 429 LOGIN_RATE_LIMITED kèm
        Header "Retry-After" trong tab Headers của Response.

(2) Request 2: Kiểm tra thiếu Header Idempotency-Key (400 Bad Request)
    - Chuẩn bị: Tạo trước 1 đơn nháp bằng POST {{base_url}}/api/v1/request-drafts (hoặc
      dán UUID 1 đơn ở trạng thái DRAFT vào biến {{request_id}}).
    - Method & URL : POST {{base_url}}/api/v1/requests/{{request_id}}/submit
    - Headers      :
        Content-Type : application/json
        X-CSRFToken  : {{csrftoken}}
        Origin       : http://127.0.0.1:5173
        (CHÚ Ý: KHÔNG thêm / bỏ trống tích chọn Header "Idempotency-Key")
    - Body (raw -> JSON): {}
    - Kiểm chứng & Chụp ảnh:
      * Status: 400 Bad Request.
      * Body JSON báo error.code = "IDEMPOTENCY_KEY_REQUIRED".
    - (Mở rộng test Replay): Tick thêm Header "Idempotency-Key" = 1 UUID v4 bất kỳ rồi
      nhấn Send 2 lần liên tiếp -> lần 2 trả Header "X-Idempotent-Replay: true" và
      "X-Correlation-ID".

(3) Request 3: Kiểm tra chống IDOR truy cập đơn phòng khác (404 Not Found)
    - Giữ nguyên Cookie đăng nhập nhân viên ở Request (1).
    - Đặt biến {{other_request_id}} = UUID 1 đơn của người/phòng ban khác mà tài khoản
      này không tham gia (không phải người tạo, người duyệt, thực hiện hay nghiệm thu).
    - Method & URL : GET {{base_url}}/api/v1/requests/{{other_request_id}}
    - Kiểm chứng & Chụp ảnh:
      * Status: 404 Not Found (che giấu sự tồn tại bản ghi theo thiết kế chống IDOR).

(4) Request 4: Kiểm tra chặn phân quyền RBAC trên API (403 Forbidden)
    - Đăng nhập Postman bằng một tài khoản vai trò APPROVER / nhân viên (không phải
      Admin và không được bật quyền can_update ở module requests_workflows).
    - Method & URL : PATCH {{base_url}}/api/v1/workspace/request-templates/{{template_id}}
    - Headers      :
        Content-Type : application/json
        X-CSRFToken  : {{csrftoken}}
        Origin       : http://127.0.0.1:5173
    - Body (raw -> JSON):
        {
          "is_active": false
        }
    - Kiểm chứng & Chụp ảnh:
      * Status: 403 Forbidden (mã lỗi từ chối truy cập phân quyền module).

   thông dịch Python 3.12 đang dùng cho dự án.
3) Nhấn biểu tượng "Testing" (hình bình thí nghiệm) ở thanh công cụ bên trái VS Code

     Chọn thư mục "tests", mẫu tên file "test_*.py". Cây Test Explorer sẽ liệt kê
     toàn bộ các hàm test trong tests/ để bấm Run và hiện dấu tích xanh Passed.
   - Nếu muốn chạy hiển thị vạch xanh cho cả Django tests (api_core/tests/):
     * Lưu ý cần đặt biến môi trường EAS_ENV=test và DJANGO_SETTINGS_MODULE=api_core.config.settings
       trong cài đặt VS Code ("python.envFile" hoặc Terminal profile).
     * Khi đánh dấu Run từng lớp test (như test_domain, test_storage, test_audit), kết
       quả vạch xanh Passed sẽ hiện cạnh mỗi hàm test và ở thanh Test Explorer.

4.1. Kiểm chứng chuỗi băm Audit Log (RFC 8785) bằng Django Management CLI
--------------------------------------------------------------------------------
Lưu ý cú pháp thực tế: Lệnh "audit_verify" BẮT BUỘC truyền tham số "--scope"
(giá trị là "ADMIN" hoặc "REQ:<uuid_cua_yeu_cau>").

- Cách 1 (Chạy từ máy host, đọc cấu hình DB trong .env):
    python manage.py audit_verify --scope ADMIN
    python manage.py audit_verify --scope REQ:<uuid_yeu_cau>

- Cách 2 (Chạy trực tiếp qua container Docker API đang chạy):
    docker exec eas-api-1 python manage.py audit_verify --scope ADMIN
    docker exec eas-api-1 python manage.py audit_verify --scope REQ:<uuid_yeu_cau>

Cách đọc kết quả:
- Chuỗi băm hợp lệ: In JSON có "status": "PASS", Exit Code = 0.
- Dữ liệu/hash bị sửa lén: In JSON có "status": "FAIL", Exit Code = 2.
- Mẹo kiểm tra trường hợp FAIL an toàn mà không làm hỏng dữ liệu thật trên Supabase:
    python manage.py test api_core.tests.test_reporting_and_cli -v 2
  (Trong bài test này có test_audit_verify_hash_chain_tamper_detected tự giả lập
  thao tác sửa lén hash và kiểm chứng CLI trả mã thoát khác 0 kèm FAIL).


4.2. Kiểm thử bất biến CSDL & Trigger (PostgreSQL / Supabase SQL)
--------------------------------------------------------------------------------
Tệp kiểm thử bất biến:
  database/EAS_Supabase_SQL/03_database_regression_DEV_ONLY.sql
(Kiểm tra RBAC PostgreSQL, RLS policy, trigger cấm UPDATE/DELETE lịch sử kiểm
toán kể cả với chủ sở hữu, separation of duties, retention hold... và tự ROLLBACK ở cuối).

[CẢNH BÁO QUAN TRỌNG]:
Tệp 03_database_regression_DEV_ONLY.sql được thiết kế để chạy trên MỘT SCHEMA EAS RỖNG
(ngay sau bước cài 00_eas_supabase_schema.sql, khi bảng app_user, config_release,
request đều chưa có dữ liệu). Nếu chạy trên DB đã có sẵn dữ liệu demo/production, câu
lệnh bảo vệ ở đầu file sẽ dừng lại với thông báo:
"Demo seed requires an empty EAS domain. Never run it on production."

- Cách chạy 03_database_regression_DEV_ONLY.sql trên môi trường Dev/Test sạch:
  * Bằng Supabase Dashboard -> SQL Editor (trên project test rỗng): mở nội dung tệp
    database/EAS_Supabase_SQL/03_database_regression_DEV_ONLY.sql -> nhấn Run.

2) Chạy bài test hồi quy hiệu năng có sẵn (dùng perf_counter):
     python manage.py test api_core.tests.test_request_workflow_scenarios -v 2

3) Chạy benchmark nhanh 200 lượt suy luận AI (NLP + XGBoost) bằng time.perf_counter():
   Chạy trực tiếp trong container eas-ai-service-1 (chỉ cần 1 dòng trên PowerShell):

   - Benchmark phân loại NLP (TF-IDF + Classifier, 200 lượt):
     docker exec eas-ai-service-1 python -c "import time, joblib, statistics; vec = joblib.load('models/nlp_vectorizer.pkl'); clf = joblib.load('models/nlp_request_type_model.pkl'); t = []; [(t0 := time.perf_counter(), clf.predict(vec.transform(['Mua 2 man hinh Dell'])), t.append((time.perf_counter() - t0)*1000)) for _ in range(200)]; print(f'NLP 200 runs: avg={statistics.mean(t):.3f}ms, max={max(t):.3f}ms')"

   - Benchmark chấm điểm rủi ro XGBoost (Finance, 200 lượt):
     docker exec eas-ai-service-1 python -c "import time, joblib, statistics, numpy as np; xgb = joblib.load('models/risk_model_finance.pkl'); X = np.zeros((1, xgb.n_features_in_)); t = []; [(t0 := time.perf_counter(), xgb.predict_proba(X), t.append((time.perf_counter() - t0)*1000)) for _ in range(200)]; print(f'XGBoost Finance 200 runs: avg={statistics.mean(t):.3f}ms, max={max(t):.3f}ms')"

   (Mục tiêu đạt: thời gian trung bình avg <= 300 ms).

4) Kiểm thử chịu tải HTTP đồng thời bằng Locust (tùy chọn):
   - Cài đặt: python -m pip install locust
   - Tạo tạm tệp locustfile.py ở thư mục bất kỳ với nội dung mẫu:
       from locust import HttpUser, task, between
       class EasApiUser(HttpUser):
           wait_time = between(0.2, 0.8)
           @task(2)
           def health_ready(self):
               self.client.get("/health/ready")
           @task(1)
           def public_ai_status(self):
               self.client.get("/api/v1/system/ai-status")
   - Chạy lệnh:
       locust -f locustfile.py --host=http://127.0.0.1:8000
   - Mở trình duyệt tới http://localhost:8089 -> nhập Number of users (vd: 30),
     Ramp up (vd: 5) -> nhấn Start Swarming để theo dõi bảng RPS, P50/P95/P99 latency
     và chụp ảnh biểu đồ hiệu năng.
